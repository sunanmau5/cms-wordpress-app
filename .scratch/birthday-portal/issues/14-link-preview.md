# 14 — The WhatsApp link and its preview

Type: grilling
Status: resolved
Blocked by: 02

## Question

The very first thing every guest sees is the WhatsApp preview card, not the site.

- The exact URL sent out, and whether French guests get a different link from English guests.
- The OG image, title and description — enough to intrigue without spoiling the disco-ball reveal.
- How the preview is tested before the link is sent to ~all guests at once.
- The accompanying WhatsApp message text, FR and EN.

## Answer

### The link
**One link for everyone: `rina-wolf.com/portal`.** Bare `/portal` routes by phone language (from [02](02-site-shell.md)), so a French phone lands on `/portal/fr`. Two links would mean maintaining two guest lists and eventually sending someone the wrong one; a wrong guess costs one tap on the toggle.

### The preview card
| Part | Value |
|---|---|
| **Image** | The disco ball on black with the chrome title — the site's own opening frame as a still, composed from existing assets. No new artwork needed. |
| **Title** | Enter the Rinaverse |
| **Description** | Tap the disco ball to get started |

**The description is English only, deliberately.** WhatsApp's crawler carries no browser language, so it always fetches the English page — meaning every guest sees the same card whatever their phone. The user's call: all guests read English, and the *site* still corrects itself per phone. Title carries the mystery, description does the work: pure mystery risks reading as a scam link in a group chat, pure clarity throws away the reveal.

### Caching — the operational risk
WhatsApp caches a link's card, sometimes for days, and it cannot be cleared once guests hold the link. **The image and text must be final before the link goes to anyone, including test sends.**

Procedure: send to **one** chat (or a group of just the user), confirm the card renders, only then send widely. If something's wrong after a wide send, the only workaround is appending `?v=2` to the URL — ugly, and it changes the link people already have.

### Out of scope
The WhatsApp message text around the link is the user's own — not part of the website work.

### Implementation note (not a decision)
The card image can be generated by Next's `opengraph-image` at `/portal` rather than exported by hand, which keeps it in sync with the real assets. Either way it must be **1200×630** and final before the first send.
